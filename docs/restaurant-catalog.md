# 餐厅配置与自定义菜单

setup 只选择种类。用餐页面顶部选择具体餐厅；每家待选和轮次独立保存，一次用餐共用门票。结束时仅结算当前餐厅，多人为房主当前餐厅。其他草稿被丢弃，不合并、不均摊。

## JSON 目录

`src/data/restaurants/types.json` 登记种类及餐厅ID；同目录每家一个 JSON，`index.ts` 显式导入并供客户端和服务端共用。添加餐厅时新增 JSON、在 types.json 对应种类登记ID，并在 index.ts 的 menus 数组导入。开发时会重新编译，已开始的用餐菜单不变。

```json
{
  "id": "my-restaurant",
  "name": "我的餐厅（示例）",
  "categories": [{"id": "meat", "name": "肉类"}],
  "products": [{"id": "beef", "name": "牛上脑", "category": "meat", "unit": "一盘80克", "price": 10, "emoji": "🥩"}],
  "valuationNote": "个人参考估值，非官方售价",
  "sources": ["根据个人实际食用份量与经验估算"]
}
```

ID 使用1至80位字母、数字、下划线或连字符，禁止 __proto__、constructor、prototype。餐厅ID在种类内唯一，分类和商品ID在餐厅内唯一；引用分类ID而非分类名称。商品名称不是标识，重命名保留ID。unit 明确数量、重量或容量，price 为这一份的人民币参考价值，按整数分计算。所有分类引用必须有效。

Catalog 的 GetCatalogInput 通过 typeId 获取固定目录、种类及餐厅列表，通过 restaurantId 获取餐厅商品；GetMenuInput 携带 typeId、restaurantId、category 查询菜品，levels 仅为旧目录兼容参数，新目录不使用。EditCatalogInput 仅保存自定义目录。公共契约自包含，页面不读取领域内部模型。

## 示例与估值依据

共九家，每家60商品：寿喜烧的牛牛、大牛、一绪；烤肉的庭院烤肉、炭火烤肉；火锅的川味火锅、清汤火锅；披萨的窑炉披萨、芝士披萨。后六家明确标为示例。餐券好价暂不纳入。

这些内容是为回本计算编写的示例，**不是任何品牌的官方菜单、官方售价或实际供应承诺**。菜名使用常见真实食材和烹饪名称；份量按自助餐的小盘、小碗、披萨切片估算。未采集或引用门店的实时菜单、价格。每个 JSON 的 valuationNote、sources 记录这一范围和估值方法；来源为编写者的常见份量与经验假设，不伪称品牌数据。

估值示例：蔬菜100克约4元，主食80克约5元，饮品200毫升约4元，肉类海鲜80克约10至14元，披萨一片80克约9至13元；沙拉、烤物、意面和汤按各文件注明的份量估算。估值用于同口径比较，不表示采购成本、市场报价或必然回本。请按自己的实际份量和经验修改。

`node scripts/restaurant-config.cjs` 可重新生成示例文件，会覆盖这些九家示例 JSON；日常维护应直接编辑对应文件。测试校验九家各60项、引用和估值有效。

## 自定义编辑

setup 滚筒的「我的餐厅」是与烤肉相同的餐厅种类，直接显示门票输入及单人／多人模式，开始后在 menu 顶部切换已保存餐厅。菜单内容来自「创造者模式」。创造者模式的 setup 面板与门票面板等高，点击「开始创建餐厅」进入本地餐厅列表，可预览、编辑、删除或新建餐厅。原有自定义目录直接保留，仍使用 custom 种类ID。

编辑页只编辑一家餐厅，填写餐厅名、菜品、分类和参考价值，底部可预览和保存。计量份量不再作为编辑字段，新菜品内部以“份”为单位，原菜品已有单位保持不变。

预览跳转到带 previewId 的 menu，只提供餐厅／分类与菜品浏览，隐藏加菜、票价编辑、购物车和下单入口。预览使用独立UI缓存，不创建或覆盖用餐会话，不连接房间，不保存历史；未保存的编辑也能预览，刷新后可恢复该预览。

分类仍有商品引用时拒绝删除，可先移动或删除商品。保存时只更新当前餐厅，保留其他已存餐厅。删除餐厅需弹窗确认，不影响活动用餐的固定菜单快照。

最多10家餐厅，每家30分类、200商品；文本长度受限，估值必须是有限正数。新编辑页要求填写餐厅名并至少添加一道菜品才可保存；旧空餐厅可以继续编辑补全。开始用餐时固定已完成菜单，并选中指定餐厅，旧空餐厅不阻塞其他餐厅的使用。自定义目录只有创建多人房间时才上传，服务端再次校验并固定。加入者无需在自己设备保存同样配置。

配置上传按UTF-8大小限制为1 MiB，WebSocket 消息上限为1 MiB加4 KiB，额外空间用于请求信封。预设房间由服务端加载预设配置，不接受客户端替换预设价格。
