# 版本4本地数据迁移

客户端与服务端均为2.0.0，manifest versionCode 为200，WebSocket 协议由共享 ROOM_PROTOCOL_VERSION 固定为2。不兼容协议返回 PROTOCOL_MISMATCH，客户端提示更新。

本地优先读取 `buffet-state-v4`，不存在时读取 `buffet-state-v3`，再回退更旧的独立键。版本3数据读取时迁移到内存模型，下一次正常保存写入版本4键，旧键不删除。读取损坏数据会报错，不静默重置历史。新文档的 version 为4。

- 历史、收藏的ID、原始日期、轮次时间、昵称、金额与菜品保持；缺少餐厅ID的记录按原名称展示。
- 非空旧会话固定「旧版菜单」快照，保留原菜品ID和估值，继续原来的待选与轮次计算；旧菜单只存在于该会话，setup 不提供新开入口。
- 空旧单人会话直接清理，不生成记录。新单人会话在所有餐厅都没有待选和轮次时退出也会清理。
- 新会话保存种类、当前餐厅ID、完整固定菜单和各店草稿；刷新恢复，修改自定义配置不会改变已开始的计算。
- 新记录增加 restaurantId、typeId、typeName。多人结束时还保存当时全员昵称；所有成员收藏同一个整桌小票ID，各自本地去重。

多人缓存改用 `buffet-room-v2`。旧 `buffet-room-v1` 身份凭证及未确认请求不会发送到新协议服务；旧缓存中的最终结果仍可导入本地历史并选择收藏。成员当前餐厅保存在对应房间缓存，与其他成员无关。房间号和UUID仍需服务端共同校验才可继续。

服务端始终为单实例内存，重启会清空活动房间，不能迁移旧进程内的房间。升级服务前应结束正在进行的用餐；已到本机的最终结果不受影响。原始ISO时间保持在服务端与Store中，仅在Vue页面按设备时区格式化。
